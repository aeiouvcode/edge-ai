Your situationEngineReality

Offline is the proof

Models download once from Hugging Face into the browser cache. After that, inference needs zero network. Load a model, switch on airplane mode, keep chatting. That is the whole point of edge AI.

What cannot run here

GPT-4 / Claude / Gemini-class models: they are hundreds of gigabytes and live in datacenters. No phone runs them, on-device, in 2026 - anyone claiming otherwise is proxying to a server. Also out: most models above ~3B parameters (RAM), image and video generation on mid-range phones, and gated models that require a Hugging Face login.

The iPhone fine print

WebGPU reaches iPhones only with iOS 26+ in Safari, and every iOS browser is Safari's engine underneath - Chrome on iPhone has exactly the same ceiling. On older iOS you get the WASM fallback: everything still works, chat models just think slowly.

Why single-threaded on WASM

Multithreaded WASM needs cross-origin isolation headers that static hosting cannot send. So the CPU fallback uses one core. WebGPU does not have this limit - another reason the GPU path feels like a different machine.

Privacy, in one breath

No account, no API key, no analytics, no server of ours anywhere. The only network calls are model files from huggingface.co, and only when you press Load. History is encrypted with your passphrase or not stored at all.

Local tool bridge

Same-origin projects can call an already-open EDGE//AI window through postMessage. Callers cannot read the vault, model cache or chat history, and cross-origin messages are ignored. The user still unlocks the app and chooses the loaded model.

Cloud cloak

Cloud routing is off by default. When it arrives, the optional cloak replaces detected private details with consistent synthetic twins before a request leaves, then restores them in the reply locally. The encrypted vault holds the mapping. Preview remains mandatory because local pattern detection cannot identify every name or secret.

Security posture

The AI engine is pinned and served from this same site, not executed from a changing CDN. A restrictive browser policy blocks cross-origin frames, forms, plugins, payment, camera, location, USB, Bluetooth and every network destination except this site and Hugging Face model hosts. Microphone access is allowed only when you press Record. The GPU runtime needs local blob modules and WebAssembly compilation; both stay inside this browser tab. Vault history uses PBKDF2-SHA-256 (250,000 rounds, random 128-bit salt) and AES-256-GCM with a fresh 96-bit nonce per write. Limits: model weights are public third-party data from Hugging Face, and a malicious or broken browser extension can still observe pages you open.
